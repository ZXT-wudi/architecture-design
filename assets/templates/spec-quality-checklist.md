# 规格质量清单（CHK）：<项目名 / 需求集>

> 用法：门禁 2 语义评审时按本模板生成一次，评审时逐条核销。规则（源自 spec-kit checklist 实践）：
> - 条目 `CHK###` 全局递增；每条带一个质量维度标签 + 至少一个追溯引用（`[REQ-xxx]` / `[NFR-xxx]` / `[蓝图 §x]` / `[Gap]` / `[Assumption]`）；**≥80% 条目必须有追溯引用**
> - 只写"这项质量要求是否被满足"的检查点，**不写行为动词**（"验证/测试 XX 功能"是测试计划的事，不是本清单的事）
> - 一次生成一次核销；核销 = 评审员判定该书面质量标准满足（不是跑测试）
> - 条目总数超过 40 条时按风险合并——清单是抽查工具，不是全量审计

- [ ] CHK002 对外部依赖的约束（超时/额度/失败行为）写清楚了吗？[REQ-xxx / Gap]
