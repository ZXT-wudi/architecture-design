# 触发可靠性评测（Trigger Evals）

description 是技能"该出手时出手"的第一机制。修改 `SKILL.md` 的 description 后，或技能出现该触发没触发/不该触发乱触发时，跑本评测。

## 怎么跑

1. 打开一个**新会话**，工作目录在本技能可被发现的位置（本仓库或 `~/.agents/skills/`）。
2. 逐条粘贴 `trigger-evals.json` 里的 prompt（不提"技能"二字，就当平常说话）。
3. 记录每条：模型是否加载了 architecture-design（可直接问"你刚才用了哪些技能"确认）。
4. 每条至少重复 2-3 次——触发有随机性，单次不作数。

## 判定与迭代

- `should_trigger: true` 的条目没触发 → description 缺该场景的关键词/说法，把用户的原话措辞补进 description（注意总长 ≤ 1024 字节）。
- `should_trigger: false` 的条目触发了 → description 太宽，收窄过泛的表述（如"即使用户随口一提"这类 pushy 句式的强度）。
- 改完 description 重测全量 20 条；连续两轮全绿即停，不要过度调（过拟合新措辞会漏未来说法）。

## 维护

- 实际使用中遇到新的误触发/漏触发说法，追加为新条目（它们是最真实的评测集）。
- 条目刻意包含：错别字、口语、具体路径/技术名——越接近真实输入越有效。
